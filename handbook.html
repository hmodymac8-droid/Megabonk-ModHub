Update checks (1.2.2)

The bug that started 1.2.2: Quest Tracker 1.3.0 was out, Nexus and Thunderstore's single-package API both said 1.3.0, but Thunderstore's full list (CDN-cached) still said 1.2.0, and the Hub only looked at Thunderstore when it had the package. A friend's Hub showed "up to date".

  1. Newer site wins. Updates.Refresh compares the Thunderstore package and the Nexus mod against the version you have and offers the higher one.
  2. Nexus ahead: the button links to the Nexus files page, and Online.CheckPackage asks thunderstore.io/api/experimental/package/<owner>/<name>/ once per Nexus version. If that has the version, it replaces the package in the list (kept even when a stale list is downloaded again) and the update installs in the Hub. While asking, clicking Update says "still checking".
  3. Matching Nexus: the package's website_url (nexusmods.com/megabonk/mods/<id>) gives the exact Nexus mod; otherwise same name and same author as the Thunderstore owner. The Hub itself always uses Nexus 194.
  4. Freshness: opening the Hub re-downloads lists older than 5 minutes; Online.Tick re-checks Thunderstore, Nexus and the GitHub release every 15 minutes while the game is open (after the first load). The 30-second retry wait after a failure still applies offline.

Tested in game: stale list at 1.2.0, Quest Tracker swapped back to 1.1.2 → the Hub showed "Update 1.3.0", logged that Thunderstore's page said 1.3.0, and installed it in the Hub.

Release checklist

  1. Bump the version in ModHub.csproj and Plugin.cs, run .\build.ps1, test in game.
  2. Check the zips: BepInEx/plugins/ModHub/ModHub.dll is the first entry, its hash matches the tested DLL, no zip or exe inside the All-in-One.
  3. Write desc_1xx.txt: English + Arabic "What's new", keep the self-update line and the credits.
  4. GitHub: gh release create vX.Y.Z -R hmodymac8-droid/ModHub dist\ModHub-X.Y.Z.zip dist\ModHub-X.Y.Z-AllInOne-with-BepInEx.zip with notes.
  5. Nexus (the user's Chrome, signed in as AhmedHus21): Files tab → set the zip into the "Add file" input → "Update existing file" → type in the "Select existing file" box and click the option → tick Archive existing file → File version → tick "Update mod version" → changelog → Save file. Don't use the per-row "Update" button.
  6. The 33 MB All-in-One goes up in 4 pieces (dist\parts, 9 MB each, upload limit is 10 MB per call): put each into a helper file input, join them in the page as one Blob, check SHA-256, then set it into the real input with DataTransfer.
  7. Description: Nexus uses SCEditor (sceditor.instance(textarea).val()); it adds [/*] after list items. Edit it in place, then Save.
  8. Wait for the virus scan to say "Safe to use" (the big file takes about 10 minutes). Keep the user's own thumbnail when changing pictures; screenshots in English.

Melon Bridge

Ships inside the Mod Hub downloads as its own plugin and can be switched off in the Hub. It converts MelonLoader mods (Cecil: Il2CppX → X), provides a stand-in MelonLoader.dll (MelonBase/Mod/Plugin, logger, preferences, coroutines, NativeHook) and a renamed MelonBridge.Newtonsoft.Json. Melon mods live in BepInEx\melon-mods. 68 of 71 surveyed Melon mods verify. Source and plan: Megabonk Mods\MelonBridge, MELON_BRIDGE_PLAN.md. BonkMenu is a cheat menu: never leave it installed.

Installer

ModHub\Installer (net48 WinForms) embeds the All-in-One, finds the game through Steam libraries, backs up replaced files, verifies every file's SHA-256, English and Arabic. Installer\test-installer.ps1 runs 11 tests. The build is byte-identical from any folder; public source at ModHub-Installer. Nexus quarantined the exe (executables need manual review); a review request was emailed to Nexus support on 22 Oct and is still waiting.
